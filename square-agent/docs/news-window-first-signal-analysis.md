# 滑动窗口首信号效应分析（修正版）

> 生成时间：2026-06-25
> 方法修正：本报告取代 `news-cluster-first-signal-analysis.md`（gap-based 方法不正确）
>
> 正确算法：按 (coin, trade_time) 排序后，**同一币种第一个信号为首信号**，
> 其后 **4h 内的同方向信号都是回声信号**；反方向或超过 4h 则为新的首信号。

## 与旧方法的差异

| 维度 | gap-based（旧，错） | sliding window（本报告） |
|---|---|---|
| 簇边界判定 | 相邻两条信号间隔 ≥ gap 则新簇 | 窗口从 primary 起算，超过 window 或反方向则新 primary |
| BTC 簇数 | 104（BTC 几乎无信号空隙） | **13,619**（方向反转即新 primary） |
| BTC 回声占比 | 99.7% | 58.3% |
| 合并 r（primary） | +0.021 | **+0.010** |
| r 提升 vs 全信号 | +0.015 | **+0.004** |

旧方法在 BTC 上失效（全年只有 104 次 4h 无新闻），新方法通过方向反转触发新 primary，能正确识别 13,619 个独立信号事件。

### 与 gap-based 方法对比（同一数据集）

| window | gap-based r | sliding r | gap-based n | sliding n |
|---|---|---|---|---|
| 2h | +0.030 | **+0.011** | 7,167 | **23,949** |
| 4h | +0.021 | **+0.010** | 4,386 | **21,890** |
| 24h | +0.039 | **+0.009** | 1,676 | **19,780** |

**gap-based 方法高估了首信号效应**：因为它在 BTC 上只能找到 104 个首信号（4h gap），把这些首信号的 r 当成"信号预测力"，实际上是**采样偏差**——只在 BTC 长时间无新闻后才取一个样本，这些样本不代表整体分布。

sliding window 方法保留了 13,619 个 BTC 首信号，统计功效更高，结果更可信：**r ≈ 0.01，不显著**。

## 5. 结论

| 命题 | 是否成立 |
|---|---|
| 同币种 4h 内常有同方向回声信号？ | ✅ 成立（BTC 58%、ETH 52%） |
| 首信号 r > 全信号 r？ | ⚠️ 弱成立（差值 +0.004，合并 r 仍 p>0.10） |
| 首信号过滤能让信号显著？ | ❌ 不成立（最强 window=2h 也仅 p=0.082） |
| 单币种有可商用信号？ | ❌ 不成立（仅 SUI 单检验显著，n=72，r 已下降） |

### 核心结论

即使用户指定的正确滑动窗口方法，**FinBERT 在 CoinDesk 标题上对 4h 价格方向仍无可用预测信号**：
- 合并 r 从 0.006 → 0.010（+0.004），统计上等同噪音
- 旧 gap-based 方法显示的 r=0.021-0.039 是 BTC 采样偏差造成的假象
- BTC/ETH 这两个流动性最高的币种 r 始终在 ±0.005 内，首信号过滤无影响

### 为什么首信号过滤无效？

1. **FinBERT 方向错误率 ~50%**：首信号的方向本身就不准，过滤回声不能修正方向错误
2. **"首信号"≠"信息源"**：CoinDesk 第一篇报道可能也是聚合/评论，而非真正的信息源（如 SEC 公告、链上事件）
3. **市场效率**：4h 窗口对 BTC/ETH 太长，价格在首信号后可能已多次均值回归
4. **回声有时携带增量信息**：TON/WLD 首信号 r 反而更低，说明后续报道（机构确认、监管回应）才是真正的价格驱动
