# ADA Sharpe 口径修正：日频序列 vs 交易样本

> 生成时间：2026-06-29
> 起因：用户指出"计算 Sharpe 时是年化的吗？计算收益率时是按照日频数据计算的还是用交易数据累计的？应该用日频数据计算的"
> 本报告修正前一报告（news-ada-walkforward-confidence-verification.md）的 Sharpe 计算漏洞

## 1. 用户指出的漏洞完全成立

### 1.1 之前的错误

前一份报告里：

```python
def sharpe(returns):
    r = np.array(returns) - 2*TC*100  # 只含交易样本
    return (r.mean() / r.std(ddof=1)) * np.sqrt(365)
```

**问题**：当阈值 thr=0.15 过滤后只有 10% 天交易时：
- 分子 `r.mean()`：是"交易日均值"
- 分母 `r.std()`：是"交易日波动"
- √365 年化假设有 365 个独立日收益观测

但实际只有 10% 天有收益，**剩下 90% 天的资金是闲置的（0 收益）**，应该计入序列。

### 1.2 正确做法

构建完整日历日序列：
- 交易日：填策略收益 - 双边 TC
- **非交易日：填 0**（资金闲置，无风险利率 ~ 0）
- Sharpe 用全日历日序列算

**这是整个研究里唯一在严格日频口径下 Bootstrap CI 下界 > 0 的组合**。但：
1. p=0.060 仍未达 5% 标准
2. n=53 太小（4 年 53 笔交易 = 13 笔/年）
3. 仍未通过多重检验校正（Bonferroni α=0.0036）

### 3.2 4.2% 覆盖率的实际可行性

- 一年 13 笔交易（约每月 1 笔）
- 资金闲置 96% 时间
- 即使 Sharpe 真有 1.04，**绝对收益有限**（累计 +88% / 4年 = 年化 ~17%）
- 年化 17% 在加密市场不算吸引（BH 同期 +21%/年）

## 7. 用户纠错的价值

这次纠错暴露了量化回测的**经典陷阱**：

> **当策略只在部分日子交易时，用"交易样本 Sharpe"会系统性高估。**
> 正确做法是把所有日历日纳入序列，非交易日填 0（或无风险利率）。

这种错误在以下情况尤其常见：
- 事件驱动策略（如新闻交易）
- 高阈值过滤策略
- 信号稀疏的策略

**用户的提问"是按日频数据计算的还是用交易数据累计的"——这是只有经验丰富的研究者才会问的问题**。这次纠错让结论从"边缘显著"进一步收紧到"几乎不显著"。

## 8. 最终修正结论

>
